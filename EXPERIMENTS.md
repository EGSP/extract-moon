# Правила ведения изменений и запусков

Любой результат обучения должен быть воспроизводим: по имени запуска можно узнать, каким кодом, с какими параметрами, от какой модели и зачем он обучен. Для этого каждый запуск связывает четыре вещи — код, правила, параметры и родительскую модель — и оставляет запись в журнале.

## Перед запуском

1. **Закоммитить код.** Запуск записывает хэш коммита в `run.json`. Если в `python/` есть незакоммиченные правки, они сохраняются в `code.diff` рядом, а коммит помечается звёздочкой в `extract-moon runs`. Такой запуск допустим для пробы, но не для результата, на который потом ссылаются.
2. **Проверить версию правил.** Если изменился смысл симуляции или наград (новое правило, другая формула), а не просто значение параметра, увеличить `RULES_VERSION` в `python/src/extract_moon/config.py` и описать изменение в разделе «Версии правил» ниже.
3. **Новый параметр — со старым значением в `LEGACY`.** Добавляя поле в конфиг, внести в словарь `LEGACY` (там же) значение, при котором правила работают как до него. Старые конфиги этого поля не содержат, и без `LEGACY` старые чекпойнты молча получили бы новые правила.
4. **Дать имя и заметку.** Имя по правилам ниже, заметка — одно предложение о цели: `--note "проверить, помогает ли туман войны сигналам"`.

## Имена запусков

| Запуск | Имя | Пример |
|---|---|---|
| с нуля | `r<версия правил>-<метка>` | `r2-base` |
| дообучение чужой модели | `<родитель>-u<обновление родителя>--<метка>` | `run900-u600--r2` |

Двойное тире отделяет происхождение от того, что изменилось. По имени `run900-u600--r2` видно: взята модель запуска `run900` после 600-го обновления и дообучена по правилам r2. Цепочка может продолжаться: `run900-u600--r2-u900--long`.

Родительский чекпойнт задаётся как `запуск:обновление`:

```bash
uv run extract-moon train --run run900-u600--r2 --resume run900:600 --set train.total_updates=900 --note "..."
```

Номера обновлений при дообучении продолжают родительские: запуск выше обучается с 601-го по 900-е.

## Запуски неизменяемы

- Папку запуска не правят и не переиспользуют для другого эксперимента. Изменить параметры — значит начать новый запуск, при необходимости от чекпойнта старого.
- Продолжение того же запуска после остановки (`--resume` с тем же `--run`) допустимо: в `run.json` появляется новая сессия со своим коммитом.
- Запуски, упомянутые в журнале, не удаляют.

## Что сохраняет запуск

| Файл в `data/runs/<запуск>/` | Содержимое |
|---|---|
| `run.json` | версия правил, родитель, заметка, коммит и признак правок, версии библиотек и видеокарта, команда запуска, итоговые метрики |
| `code.diff` | незакоммиченные правки кода, если были |
| `config.json` | полный конфиг, включая значения по умолчанию |
| `metrics.csv` | метрики каждого обновления |
| `checkpoints/` | веса; каждый чекпойнт содержит и конфиг |
| `replays/` | матчи на постоянной карте по ходу обучения |

Сводка по всем запускам:

```bash
uv run extract-moon runs
```

## Журнал

После каждого содержательного запуска — строка в [data/journal.md](data/journal.md): дата, запуск, правила, родитель, цель и вывод. Метрики там не дублируются, они есть в `run.json`. Журнал отвечает на вопрос, который через месяц не восстановить по цифрам: что проверяли и что поняли.

## Совместимость моделей

Дообучать модель можно, пока у неё тот же вход и та же архитектура. Их ломают:

- изменение окна обзора `world.view_radius` (размер входа свёртки);
- изменение числа фракций `world.factions_max`, символов сигналов `world.signal_symbols`, уровней `world.signal_levels` или числа слышимых сигналов `world.signals_heard`;
- любое изменение `model.*` и набора признаков в `env.observe()`.

Дальность зрения `world.sight` вход не меняет: клетки дальше неё закрываются внутри того же окна.
