# Python-часть Extract Moon

Симуляция, модель RWKV, обучение PPO, запись реплеев и временный проигрыватель на pygame.

## Окружение

Драйвер NVIDIA 472.12 не обновляется (на GTX 1050 новые драйверы дают BSOD), он поддерживает CUDA до 11.4.
Версии подобраны под это ограничение:

| Пакет | Версия | Почему |
|---|---|---|
| Python | 3.12 | поддерживается torch 2.7; 3.14 в системе для torch 2.7 не подходит |
| torch | 2.7.1+cu118 | последняя ветка со сборкой CUDA 11.8; сборки 11.x работают на драйвере ≥ 452.39 благодаря minor version compatibility, сборки CUDA 12 требуют драйвер ≥ 527 |
| numpy | 2.0–2.2 | совместим с torch 2.7 |
| pygame-ce | 2.5 | проигрыватель реплеев и экспорт GIF |

Установка (нужен [uv](https://docs.astral.sh/uv/)), из папки `python/`:

```bash
uv sync
```

```bash
uv run python tools/check_gpu.py
```

## Команды

Все команды выполняются из папки `python/`.

```bash
uv run extract-moon train --run r2-base --note "зачем этот запуск"
```

Параметры переопределяются через `--set`, например `--set train.total_updates=500 reward.faction_share=0`.
Продолжить или дообучить: `--resume run900` (последний чекпойнт) или `--resume run900:600`.
Как называть запуски и что фиксировать перед ними — в [EXPERIMENTS.md](../EXPERIMENTS.md).

Сводка всех запусков (правила, родительская модель, коммит, итог):

```bash
uv run extract-moon runs
```

### Просмотр обучения

Проще всего — **проводник запусков**: двойной щелчок по `Запуски.bat` в корне проекта. В окне дерево
запусков (дообученные — веткой под родителем), их состояние и итоги, кнопки «Матчи», «Графики»,
«Сравнить с родителем», «Папка» и «Журнал запусков». Под ними — сохранённые модели запуска на шкале
обновлений поверх кривой взлётов: видно, какая модель была удачной и от какой пошли дообучения.
Выбранной моделью можно сыграть новый матч на случайной карте, открыть её матч этапа или скопировать
команду дообучения от неё. Список обновляется сам. Из командной строки:

```bash
uv run extract-moon explorer
```

Живые графики, перерисовываются по мере записи метрик (можно передать несколько запусков для сравнения):

```bash
uv run extract-moon watch r2-base
```

Те же графики в PNG (`data/runs/r2-base/metrics.png`):

```bash
uv run extract-moon plot r2-base
```

Каждые `train.replay_every` обновлений обучение записывает матч на одной и той же карте
`train.replay_seed` в `data/runs/<запуск>/replays/`. Проигрыватель открывает их все сразу;
новые этапы подхватываются на лету:

```bash
uv run extract-moon view r2-base
```

Управление проигрывателем — кнопками внизу окна: в начало, такт назад, пуск и пауза, такт вперёд,
в конец; скорость (по умолчанию такт в 2 секунды); предыдущий и следующий этап обучения — на том же
такте; зоны обзора фракций; плавное движение роботов и проявление сигналов между тактами; снимок; GIF. Клик по полосе времени переходит к такту, клик по роботу
показывает вероятности его решений, а справа видно, кто занял места в корабле.
Клавиши дублируют кнопки: пробел, ←/→, ↑/↓, V, I, S, G, Tab.

Зоны обзора залиты цветом фракции; где зоны нескольких фракций пересекаются, клетка заштрихована
их цветами.

## Устройство

- `config.py` — все параметры мира, наград, модели и обучения; сохраняется в каждый запуск и чекпойнт.
- `env.py` — headless-симуляция, векторизованная по numpy сразу по всем матчам и роботам.
- `model.py` — кодировщик (свёртка по окну обзора + признаки), RWKV в рекуррентной форме, головы:
  действие, улучшение, символ сигнала, уровень сигнала, критик.
- `train.py` — PPO: сбор опыта отрезками, GAE по потокам роботов, BPTT по отрезку от сохранённой памяти.
- `replay.py` — запись и чтение реплеев.
- `viewer.py` — проигрыватель (с переключением этапов обучения) и экспорт GIF.
- `metrics_view.py` — живые графики обучения и сравнение запусков.
- `explorer.py` — проводник запусков (tkinter).
- `provenance.py` — паспорт запуска `run.json`: коммит, правки кода, родитель, заметка.
- `tools/` — проверка GPU и замер скорости.

## Решения MVP по открытым вопросам

Эти правила выбраны для первой версии и вынесены в конфиг, чтобы их можно было менять:

- Карта клеточная; в одной клетке может стоять несколько роботов, поэтому движения не конфликтуют.
- «Рядом» означает соседнюю клетку, включая диагональ, или ту же клетку.
- Мешать можно атакой: она снимает прочность цели и отбирает часть её энергии. Спящим урон удвоен.
- Улучшения: ёмкость, броня, скорость добычи. Каждый уровень стоит энергии и увеличивает расход за такт.
- Сесть в корабль можно в любой момент, пока есть места (в r3 их 5–6). Пассажир стоит в клетке корабля, и с правил r3
  (`world.passenger_damage`) его может атаковать чужой робот рядом с кораблём; погибший пассажир освобождает место.
  После полной зарядки корабль ждёт `launch_delay` тактов и улетает (или раньше, если места кончились).
  Если корабль не зарядили за `max_steps` тактов или не осталось бодрствующих роботов, проигрывают все.
- Робот знает направление на корабль (маяк), но заряд и число мест видит, только находясь в пределах зрения.
- Зрение (`world.sight`, 4 клетки) короче окна обзора (`world.view_radius`, 5): дальние клетки окна
  закрыты туманом. Так дальность зрения меняется без изменения входа сети.
- Погибший робот (`reward.dead_wait`) получает −5 сразу, а в конце матча — свою долю за улетевших
  союзников. Неулёт корабля стоит −5 всем живым, то есть равен гибели; погибшим повторно не начисляется.
- Свой или чужой отправитель сигнала, робот понимает, только если видит его.
- Недопустимые действия маскируются (например, «зарядить корабль» вдали от него).
- Головы сети стартуют со смещением против дорогих действий (уйти из фракции, размножиться, улучшиться,
  подать сигнал). Иначе необученная сеть за первые такты распускает фракции и сжигает энергию.
- Стартовый баланс правил r1 (карта 14–18 клеток, капсулы на 0,35 размера карты от центра, корабль на
  80–120 энергии, награда 0,2 за единицу заряда) подобран так, чтобы обучение с нуля сдвинулось. При капсулах на 0,4 карты
  от центра и меньшей награде сеть за первые 60 обновлений выучивает только «стоять на месте и не засыпать»,
  а с этими настройками заряд корабля к концу матча растёт с 5 % до 19 % за то же время.
  В правилах r2 карта вдвое больше (28–36 клеток), горячих точек 6–9, матч до 400 тактов.
  В r3 карта и матч снова как в r1: при большой карте и коротком зрении робот видел около 8 % карты.
